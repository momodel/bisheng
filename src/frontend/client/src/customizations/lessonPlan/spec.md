# 教案助手

本次按单模块、无后端契约变更的轻量流程迁移。应用 ID 和原编辑器入口统一在 `customizations/config.ts` 维护；聊天仍使用 BiSheng。

## 验收标准

1. 仅教案助手的 `/custom-app` 消息识别顶层 `markdown-lesson` 围栏，渲染教案卡片。正文复用现有 Markdown，普通文字和其他应用行为不变。
2. 流式输出可预览正文；消息正常结束、围栏闭合且内容非空后，才允许“新页面打开”。只读／访客隐藏操作。
3. 使用当前 `localStorage.token`，通过根路径 POST `/pyapi/course/v3/teaching_plan/cache` 发送 `{cache_id, markdown_content}`；确认 `{message: "ok"}` 后进入同域 `/adminManage/AiLessonEditor`，保留查询参数。
4. 缓存 ID 优先取 `unitId`，其次 `cache_id`。按用户确认完全沿用原版：没有这两个参数时只显示教案内容，隐藏“新页面打开”，不生成临时 ID。课程名称和加入课程继续依赖原编辑器的 `courseId`／`unitId`。
5. 新建、切换、删除最后一条会话后保留当前教案上下文参数；切换到其他应用不携带。入口路由继续透传查询参数。
6. 上传防重复点击；失败关闭占位页并可重试；弹窗被拦截时提示且不写缓存；每次打开重新缓存，避免依赖已过期或被编辑过的内容。
7. 卡片沿用现有定制模块风格，支持窄屏，新增文案提供中文／英文／日文。

## 边界

原编辑器继续提供编辑、保存、Word 下载和加入课程，不复制这些能力到 BiSheng。原后端缓存按用户与缓存 ID 隔离，有效期 24 小时。相同 `unitId`／`cache_id` 的再次打开会覆盖同一缓存，与原项目一致。教案参数为当前入口上下文，不会持久化绑定到 BiSheng 会话记录；直接打开不带参数的历史地址只预览内容。
