# F053 设计

## 迁移协议

脚本使用版本化 JSON 包 `bisheng.mo-app-bundle/v1`。源端只写本地包，目标端单独运行预检与导入，因此不要求两个环境同时可达。包内不保存工具 API Key。

导入顺序为：完整预检 → API 工具 → 工具权限 → 工作流及版本 → 工作流权限 → 助手 → 助手权限 → 助手关联与 MO 标签。所有应用强制下线。

## 引用转换

- 应用 ID、助手关联的工作流 ID保持不变。
- API 工具在目标端获得新数据库 ID 和 `tool_key`，脚本重写工具节点及 Agent `tool_list` 中的 ID/Key。
- 预置工具不复制，目标必须存在相同 `tool_key`。
- `model_id` 与 `recommended_llm` 参数改为目标工作流默认 LLM；助手 `model_name` 改为目标助手默认 LLM。
- 知识库不进入迁移包：助手知识库 Link 被丢弃；工作流知识选择、元数据过滤、知识鉴权开关和相关 rerank 配置被清空，同时记录警告。

## 权限

脚本只通过 F048 资源适配器创建受保护的 `admin` 所有者投影，再通过 `InitialGrantApplication` 添加根部门 `viewer` Grant。不会直接写 OpenFGA tuple 或旧权限表。

## 失败策略

所有可确定条件在首次写入前检查。ID/名称冲突、模型缺失、预置工具缺失或 MCP 依赖会返回退出码 3。知识库引用只产生丢弃警告。写入阶段的基础设施异常返回退出码 4，并输出已发生的操作；运行前仍应按维护脚本要求备份目标数据库。
