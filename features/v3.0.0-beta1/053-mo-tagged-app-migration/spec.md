# F053 MO 标签应用迁移

## 目标

提供可在两个 BISHENG 环境分别运行的命令行脚本，导出并导入标签为 `MO` 的工作流和助手。导入后原有 `mo-agent/flow/{id}` 地址继续有效。

## 验收标准

1. 导出 MO 标签关联的工作流、助手、全部未删除工作流版本及其引用的 API 自定义工具。
2. 工作流与助手 ID 原样保留；目标存在同 ID 资源时预检失败，禁止覆盖。
3. 目标创建人为唯一且有效的全局超级管理员 `admin`，应用保持下线。
4. 助手模型替换为目标系统设置中唯一标记为默认的助手 LLM；工作流 LLM 节点替换为目标工作流默认 LLM。对应默认模型缺失、下线或不是 LLM 时禁止导入。
5. 导入的 API 自定义工具认证固定为无认证，不携带 API Key；OpenAPI 声明认证时输出待配置警告。
6. 新应用和新工具保留 `admin` 所有者权限，并给目标租户根部门授予 `viewer`，`include_children=true`。
7. 导入默认只执行预检，只有 `--apply` 才写入。
8. MCP 不在迁移范围，存在实际引用时整批预检失败。知识库同样不迁移，但不阻塞：助手知识库关联不导出，工作流知识库选择、元数据过滤和对应 rerank 设置清空，并输出警告。

## 非目标

- 不迁移用户、用户组或来源环境的权限明细。
- 不迁移模型供应商、模型密钥、知识库数据、MCP 配置或对象存储文件。
- 不自动上线应用。
